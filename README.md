# ГК «РОСЭКО» — сайт испытательной лаборатории

Новая сборка проекта: Next.js 15 (App Router) + React 19 + TypeScript, без UI-библиотек.
Стили — одна дизайн-система в `app/globals.css` на CSS-переменных, mobile-first.
Тексты вынесены из вёрстки в `lib/`, поэтому правки контента не трогают компоненты.

## Команды

```bash
npm install
npm run dev        # разработка, http://localhost:3000
npm run build      # сборка
npm run build:static  # статика для GitHub Pages -> папка out/
npm start          # запуск собранного сайта, 0.0.0.0:3000
npm run typecheck  # tsc --noEmit

# проверки (нужен запущенный сайт: npm start в отдельном терминале)
npm run check:mobile   # вёрстка на 360/390/768/1280/1440 + снимки в checks/
npm run check:a11y     # axe-core, WCAG 2.1/2.2 AA, десктоп и мобильный
npm run check:perf     # CLS и LCP, мобильный профиль (4× CPU) и десктоп
```

Обе проверки должны заканчиваться «нарушений не найдено». Скриншоты складываются в `checks/`.

### Офлайн-предпросмотр (один файл со всем сайтом)

Два скрипта собирают автономные HTML-файлы — их можно открыть без сервера и интернета
(шрифты, стили и фотографии вшиты внутрь). В репозиторий они не коммитятся: это артефакт,
его всегда можно пересобрать.

```bash
python3 scripts/build-all-in-one.py   # preview-all.html — все 14 страниц скроллом
python3 scripts/build-offline.py      # preview-main.html — 14 страниц с меню и навигацией
                                      # (нужен запущенный npm start на :3000)
```

### Проверить статику перед публикацией

```bash
NEXT_PUBLIC_BASE_PATH=/имя-репозитория npm run build:static   # сборка в out/
NEXT_PUBLIC_BASE_PATH=/имя-репозитория python3 scripts/serve-static.py
# → http://localhost:8000/имя-репозитория/
```

`scripts/serve-static.py` отдаёт `out/` так же, как это делает GitHub Pages:
в подпапке репозитория, без расширения `.html` и с `404.html` для несуществующих
адресов. Это ловит битые пути до публикации.

## Дизайн-система

- Палитра на переменных: `--ink #65542F` (7.3:1), `--ink-soft #55606C` (6.4:1),
  акцент для текста `--terracotta-text #9E4622` (≥4.8:1 на всех подложках),
  заливка кнопок `--terracotta-strong #B5532F` (белый текст 4.95:1),
  тёмный `--ink-deep #2E2718`, зелёный текст `--sage-deep #3F5A45` (7.6:1)
  и зелёно-серый поясняющий `--sage-gray #5A6B5E` (5.7:1) — блок «Оснащение».
  Все пары проверены под AA и выше.
- Шаг сетки 8 px, контейнер 1180 px, секции 96 px / 56 px (десктоп / мобильный).
- Брейкпоинты: 700 px и 1024 px. Мобильная версия проектируется первой.
- Цели нажатия не меньше 44 × 44 px (кнопки 48–52 px, поля 52 px, шрифт полей 16 px —
  иначе iOS зумит страницу при фокусе).
- Изображения: `next/image` с `sizes`, аспект задан заранее (CLS = 0),
  `object-position` подобран так, чтобы кадр не терял смысл при обрезке.
- Первый экран: фотография на всю ширину + постоянный скрим (без него белый текст
  на воде и небе даёт 2–3:1), текст в левой колонке — человек в кадре остаётся виден.

## Решения, которые стоит знать

- **Заявку принимаем по телефону.** Формы на сайте нет: для расчёта нужно уточнить
  объект, показатели и сроки, а это быстрее выяснить голосом. Все кнопки ведут
  на `tel:` или в блок контактов (`/kontakty#zayavka`).
- **В первом экране — сообщение о том, как устроена работа** («пробы забираем на месте,
  протоколы отдаём в срок»), без цитат от лица чужих сотрудников и без выдуманных
  обещаний. Цифры о себе живут в блоке «О компании».
- **Карта встроена** через виджет и грузится лениво; рядом — адрес и кнопка
  «Открыть на карте». Пока карта не отрисовалась, внутри блока виден адрес —
  пустого прямоугольника на её месте не бывает.
- **Блок «Оснащение» — текстом, без плашек.** Два факта о лаборатории («с 2010 года»,
  «Shimadzu») набраны как текст: значения — зелёным `--sage-deep`, пояснения — зелёно-серым
  `--sage-gray`, разделены воздухом и тонкой линией. Карточки-плашки читались как кнопки
  и спорили с фотографией панели ниже, поэтому от них отказались.
- **Опубликованных цифр по договорам нет**: названия заказчиков и метрики проектов
  без письменного согласия не публикуем. В примерах работ — только типовые задачи.
- PDF-ссылки живут в `public/docs/`, имена файлов менять не нужно — достаточно
  перезаписать файл, вёрстка не изменится.

## Публикация на GitHub Pages

Сайт живёт по адресу `https://<владелец>.github.io/<репозиторий>/`. Pages — хостинг
статики: он не умеет запускать Node.js и собирать Next.js, поэтому сборка выполняется
в GitHub Actions (`.github/workflows/deploy.yml`), а на хостинг уезжает готовая
папка `out/` — только HTML, CSS, JS и картинки. Исходники в репозитории остаются
чистыми, ничего собирать руками не нужно.

Настройка один раз:

1. **Settings → Pages → Source: GitHub Actions** (не «Deploy from a branch»).
2. Загрузить проект в репозиторий и запушить в ветку `main`.

Дальше каждый `git push` в `main` пересобирает и публикует сайт: 1–2 минуты, прогресс
виден во вкладке **Actions**. Отдельно запустить сборку можно кнопкой *Run workflow*.

Что знает сборка:

- `basePath` считается из имени репозитория (`/roseco48` для репозитория `roseco48`) —
  переименование или форк ничего не ломает. Исключение: репозиторий вида
  `<владелец>.github.io` публикуется в корне, и тогда `basePath` не нужен — это учтено;
- `NEXT_PUBLIC_SITE_URL` подставляется в `sitemap.xml`, `robots.txt` и микроразметку,
  чтобы в них стоял реальный адрес сайта, а не черновой домен;
- картинки отдаются как есть (`images.unoptimized`) — статический хостинг не умеет
  сжимать их на лету, поэтому все размеры подобраны заранее.

Если в имени репозитория есть заглавные буквы, укажите `NEXT_PUBLIC_BASE_PATH` вручную
в workflow: адреса на Pages чувствительны к регистру.

### Если публиковать без Actions

Можно собрать статику локально и загрузить папку `out/` вручную:

```bash
NEXT_PUBLIC_BASE_PATH=/имя-репозитория npm run build:static
```

Затем положить содержимое `out/` в ветку `gh-pages` (или в папку `/docs` ветки `main`)
и выбрать её в Settings → Pages. Файл `.nojekyll` в сборке уже есть — он нужен, чтобы
GitHub не трогал папку `_next` своим обработчиком Jekyll. Этот путь требует ручной
пересборки после каждой правки, поэтому по умолчанию используется Actions.

### Как выложить проект (архив)

```bash
cd ros-eco
git init
git add .
git commit -m "Сайт испытательной лаборатории ГК «РОСЭКО»"
git branch -M main
git remote add origin git@github.com:ВАШ-ЛОГИН/имя-репозитория.git
git push -u origin main
```

Если репозиторий уже создан на github.com, можно обойтись без консоли: распаковать архив
и перетащить файлы в веб-интерфейс. Что не попадёт в репозиторий — перечислено в
`.gitignore`: `node_modules/`, `.next/`, `out/`, `checks/`, `preview-*.html`, `.env`.

## Производительность

Статические страницы (21 маршрут), первый JS — 102–115 кБ на страницу,
изображения в AVIF/WebP, шрифт Inter подключается локально через `next/font`.
Смещений макета нет: у всех изображений и у карты заданы размеры.

## Проверено

- `npm run typecheck` — без ошибок;
- `npm run build` — 21 маршрут, ошибок нет;
- `npm run check:mobile` — горизонтальной прокрутки нет, элементов за краем нет,
  все цели ≥44 px, все изображения загружаются и имеют `alt`, заголовки без пропусков;
- `npm run check:a11y` — нарушений WCAG AA нет (в том числе контрасты) на 9 страницах
  в десктопном и мобильном вариантах;
- `npm run check:perf` — CLS = 0.000 на всех 7 проверяемых страницах; LCP 1,46 с на
  главной в мобильном профиле с четырёхкратным замедлением процессора и 0,1–0,3 с
  на остальных страницах (порог «хорошо» — 2,5 с).

### Про подбор размеров изображений

`sizes` у каждого кадра должен совпадать с реальной шириной слота в сетке: иначе браузер
скачает слишком мелкий файл и фото будет мылить. У четырёх кадров на главной слот
534 px, и `sizes` для них выставлен по этой цифре. Если менять сетку (число колонок,
ширину контейнера), за `sizes` нужно посмотреть ещё раз — проверяется одним запросом
в консоли: `document.querySelectorAll('img')` и сравнение ширины слота с `?w=` в `src`.
